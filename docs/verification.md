# 검증 가이드 — 시간·IP 바꾸기와 9장 시나리오

## 1. 시간·IP 바꾸는 법

개발 모드(`npm run dev`)에서는 화면 우측 하단 **🛠 디버그** 버튼으로 디버그 패널을 엽니다.

- **서버 시각 변경**: 날짜·시간(서울 기준)을 고르고
  - `흐르게`(offset): 그 시각부터 시간이 흐릅니다.
  - `고정`(fixed): 그 시각에 멈춥니다. 경계값(10:00:00 / 10:00:01 등) 테스트에 씁니다.
  - **실시간으로 되돌리기**: real 모드.
- **IP 위장**: "내 IP를 ___로 가정" 에 IP 를 넣고 적용하면, 이후 모든 API 요청에 `X-Debug-Client-IP` 헤더가 붙습니다(브라우저 localStorage 에 저장). 해제하면 다시 `127.0.0.1`.
- 헤더의 🕒 시계는 항상 **서버 시각**입니다(서버가 준 값 위에서 tick, 클라이언트 시계 미사용). 고정/오프셋 모드면 배지가 붙습니다.

API 로 직접 바꿀 수도 있습니다 (`ENABLE_TIME_TRAVEL=true` 일 때만 존재):

```bash
curl http://localhost:3000/api/dev/clock
curl -X PUT http://localhost:3000/api/dev/clock -H 'content-type: application/json' \
     -d '{"mode":"fixed","at":"2026-11-16T09:00:00"}'     # 타임존 없으면 Asia/Seoul
curl -X PUT http://localhost:3000/api/dev/clock -H 'content-type: application/json' -d '{"mode":"real"}'
```

> 시각 상태는 서버 메모리에 있어 **백엔드를 재시작하면 real 로 돌아갑니다.**

## 2. 9장 시나리오 원클릭 재현

디버그 패널 맨 위 **「9장 시나리오 재현」** 에서 T-01 ~ T-21 중 하나를 고르고 **재현** 을 누르면:

1. 근태·신청·잔여 데이터를 비우고 (계정·공휴일·연구실 IP·이력은 유지)
2. 시나리오의 "준비" 상태를 **실제 서비스 로직으로** 만든 뒤 (예: T-15 는 연차원의 토요일 근무 신청 → 리드 승인)
3. 서버 시각을 준비 시각에 `고정` 하고, 필요한 IP 위장을 걸고, 해당 계정으로 **자동 로그인** 해서 화면으로 이동합니다.

패널에 **할 일 단계와 기대 결과** 가 표시되고, 시각을 옮겨야 하는 단계(예: T-15 "14:00 으로 이동해 퇴근")에는 **이동 버튼** 이 붙습니다. 화면에서는 "행동"만 하면 됩니다. **데이터 초기화** 는 데이터를 비우고 시각·IP 를 실시간/해제로 되돌립니다.

- API: `GET /api/dev/scenarios`, `POST /api/dev/scenarios/:id`, `POST /api/dev/reset` (`ENABLE_TIME_TRAVEL=true` 일 때만)
- 시나리오 정의: [`backend/src/dev/scenarios.ts`](../backend/src/dev/scenarios.ts). 모든 시나리오의 준비 단계가 규칙을 통과하는지와 주요 기대 결과는 `backend/test/dev-scenarios.spec.ts` 가 검증합니다.

## 3. 9장 시나리오 수동 재현

원클릭 재현 없이 손으로 따라 할 때의 절차입니다. 날짜 기준: 2026-11-16(월) ~ 11-20(금), 11-21(토), 11-23(월). 시각은 디버그 패널에서 `고정` 으로 맞춥니다. 각 시나리오를 독립적으로 보려면 패널의 **데이터 초기화** 를 누르세요.

| #    | 재현 방법                                                                                                                | 기대 결과                                                                                        |
| ---- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| T-01 | 시각 `2026-11-16 06:59:59` → kim 로그인 → 홈                                                                             | 출근 버튼 비활성, 툴팁 "출근은 07:00부터…". API 는 `ATT_TOO_EARLY`                               |
| T-02 | `2026-11-16 10:00:00` → 출근                                                                                             | 정상 (지각 배지 없음)                                                                            |
| T-03 | (DB 초기화 또는 다른 계정) `10:00:01` → 출근                                                                             | 지각 배지                                                                                        |
| T-04 | `09:00` 출근 → `15:59`                                                                                                   | 퇴근 버튼 비활성 "퇴근은 16:00부터…" (`ATT_CHECKOUT_TOO_EARLY`)                                  |
| T-05 | `09:00` 출근 → `18:00` 퇴근                                                                                              | 8시간 00분, 판정 없음                                                                            |
| T-06 | `09:00` 출근 → `17:59` 퇴근                                                                                              | 7시간 59분, 조퇴                                                                                 |
| T-07 | `12:00` 출근 → `20:00` 퇴근                                                                                              | 「내 근무」 점심 차감 30분, 7시간 30분, 조퇴                                                     |
| T-08 | `13:00` 출근 → `21:00` 퇴근                                                                                              | 점심 0분, 8시간, 정상                                                                            |
| T-09 | T-15 로 OFF 를 받은 뒤 `11-23 09:00` yeon 이 11-24 반일 OFF 신청 → kim 승인 → `11-24 13:00` 출근 → `17:00` 퇴근          | 지각 없음, 240분 정상, OFF 배지                                                                  |
| T-10 | `11-16 09:00` 출근(퇴근 안 함) → `11-17 09:00` 출근 버튼                                                                 | "퇴근 미기록" 모달 → 18:00 입력 → 어제 '직접 입력' 배지(홈의 직접 입력 목록) + 오늘 출근         |
| T-11 | `11-20 17:00:00` → 신청: 연차, 11-23                                                                                     | 미리보기 "이 날짜의 신청 마감: 11/20(금) 17:00", 제출 성공                                       |
| T-12 | `11-20 17:00:01` → 같은 신청                                                                                             | "(마감됨)" 안내, 제출 버튼 비활성 (API `REQ_DEADLINE_PASSED`)                                    |
| T-13 | yeon 으로 12월 재택 2건 신청 → 3번째                                                                                     | "재택은 한 달에 2회까지…" (`REQ_REMOTE_LIMIT`)                                                   |
| T-14 | `11-19` yeon: 주말 근무 11-21, IP `10.0.0.5`, 10:00~15:00 → kim 승인 → 시각 `11-21 09:59`, IP 위장 `10.0.0.5`            | 차단 페이지 "허용되지 않은 IP입니다: 10.0.0.5 / 서버 시각 …"                                     |
| T-15 | 위에서 시각 `11-21 10:00` → 다시 시도 → yeon 출근 → `14:00` 퇴근                                                         | 기록됨, 「잔여」 OFF 1개, 만료 2026-12-21 23:59:59                                               |
| T-16 | IP 위장 해제, 시각 `2026-12-22 09:00` → yeon 이 12-23 OFF 신청                                                           | 미리보기 "사용일 기준으로 유효한 OFF가 없습니다(만료)", 「잔여」 OFF 0, 상태 "만료"              |
| T-17 | 시각 `2026-02-01 00:00:00` → 각 계정 「잔여」                                                                            | 김근태 1일, 연차원 0일, 임자율 0일                                                               |
| T-18 | 시각 `2026-03-12 00:00:00` → lim 「잔여」                                                                                | 1일 (`03-11 23:59:59` 엔 0일)                                                                    |
| T-19 | `11-20` yeon: 재택 11-23, IP `1.2.3.4`, 08:00~19:00 → kim 승인 → 시각 `11-23 09:00`, IP 위장 `1.2.3.4` → kim 으로 로그인 | 로그인은 되지만 바로 차단 페이지 (본인 신청 아님). yeon 으로 로그인하면 정상, 출근하면 "재택"    |
| T-20 | yeon 로그인 후 `/approvals` 주소 직접 입력 / `curl` 로 `/api/dashboard/team`                                             | "접근할 수 없는 페이지입니다" + 홈 버튼 (없는 주소와 같은 화면), API 는 403 `FORBIDDEN`          |
| T-21 | 아무 행동 후 kim 「이력」                                                                                                | 모든 요청이 서버 시각·실제 시각과 함께 기록. `IP_DENIED`·`FORBIDDEN`·`LOGIN_FAIL` 도 필터로 확인 |

시간 조작으로 확인하는 완료 기준: 연차 적립(T-17/18, 「잔여」의 다음 적립일), 재택 월 초기화(12월 2건 사용 후 시각을 2027-01-01 로 → 「잔여」 재택 2/2), OFF 만료(T-16).
