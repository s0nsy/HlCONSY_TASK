# 근태 제도 해석 규칙

요구사항 원문 규칙과, 원문만으로 판단할 수 없던 부분을 어떻게 해석·결정했는지 근거와 함께 정리합니다. 규칙 상수는 모두 `backend/src/common/policy.config.ts` 한 곳에 있습니다.

## 1. 원문 규칙

| 항목            | 규칙                                                                  |
| --------------- | --------------------------------------------------------------------- |
| 출근            | 07:00 부터 등록 가능. 10:00:00 을 넘기면 지각                         |
| 퇴근            | 16:00 부터 등록 가능                                                  |
| 근무시간        | 퇴근 − 출근 − 점심(11:30~12:30 과 겹치는 만큼)                        |
| 조퇴            | 근무시간 8시간 미만                                                   |
| 재택            | 한 달 2회, 이월 없음. 재택 때도 출퇴근 등록                           |
| 연차            | 입사일 기준 매월 +1일                                                 |
| OFF             | 주말·공휴일에 근무하면 반일 OFF 1개 지급. 지급일로부터 30일 안에 사용 |
| 반일 OFF 사용일 | 퇴근 16:00 제한 없음, 근무 4시간 이상이면 정상                        |
| 신청 기한       | 연차·재택·OFF·주말/공휴일 근무 모두 전 영업일 17:00 까지              |

## 2. 요구사항 5장의 기본 해석

**공통**

- **C-1** 모든 판정은 `ClockService.now()` 기준, 타임존 `Asia/Seoul`. 코드에서 `new Date()` / `Date.now()` / `dayjs()` 직접 호출 금지 — `test/no-direct-clock.spec.ts` 가 소스를 검사합니다.
- **C-2** 영업일 = 토·일·공휴일이 아닌 날. 공휴일은 `holiday` 테이블.
- **C-3** 기록은 초 단위, 근무시간은 분 단위(초 버림).
- **C-4** 근무일은 출근한 날짜. 퇴근은 같은 날 23:59:59 까지만, 자정을 넘기면 "퇴근 미기록".

**출근** — A-1 평일 07:00:00 이상(이전엔 버튼 비활성 + API 거부 `ATT_TOO_EARLY`) · A-2 10:00:00 정상, 10:00:01 부터 지각 · A-3 하루 1회 · A-4 승인된 연차일은 출근 불가 `ATT_ANNUAL_LEAVE_DAY` · A-5 반일 OFF 사용일은 지각 판정 안 함 · A-6 재택일도 같은 규칙, IP 는 신청 IP·시간대.

**퇴근·근무시간** — B-1 평일 16:00:00 이상(반일 OFF 사용일 제한 없음) · B-2 16:00 이전 퇴근 불가 `ATT_CHECKOUT_TOO_EARLY` · B-3 점심은 근무 구간과 `[11:30, 12:30]` 이 **겹치는 만큼만** 차감(최대 60분; 원문 "포함될 때만 제외"를 부분 겹침까지 공정하게 확장한 해석) · B-4 `< 480분` 조퇴, 480분 정상 · B-5 반일 OFF 사용일 `≥ 240분` 정상 · B-6 주말·공휴일 근무는 지각·조퇴 판정 없음 · B-7 지각·조퇴 배지는 동시에 붙을 수 있음.

**퇴근 미기록·직접 입력** — M-1 출근만 있고 날이 지난 근무일 · M-2 다음 출근 버튼을 누르면 모달이 먼저 뜨고, 여러 건이면 오래된 순서로 전부 입력해야 출근이 등록됨(한 트랜잭션) · M-3 그날 출근 이후 ~ 23:59:59, 평일은 16:00 이상(반일 OFF 예외), 주말 근무는 신청 시간대 안 · M-4 `source = MANUAL` → '직접 입력' 배지, 근무시간·조퇴는 같은 방식으로 계산 · M-5 주말 근무 퇴근을 직접 입력해도 OFF 지급, 지급일 = 근무일.

**주말·공휴일 근무** — W-1 사전 신청(승인) 필수, 없으면 연구실 IP 여도 출근 불가 · W-2 출근·퇴근 모두 신청 시간대 `[start, end]` 안 + 신청 IP, 07:00/16:00 제한 없음 · W-3 시간대 밖 접속은 IP Guard 가 차단(신청 IP 가 연구실 IP 가 아닌 경우) · W-4 퇴근이 기록되면 반일 OFF 1개(근무시간 최소 기준 없음), 같은 날 중복 지급 없음.

**신청** — R-1 `ANNUAL`/`REMOTE`/`OFF`/`HOLIDAY_WORK` · R-2 공통: 날짜·사유, REMOTE·HOLIDAY_WORK: IP + 시간대, OFF: 오전/오후(표시용) · R-3 사용일 직전 영업일 17:00:00 까지(17:00:01 부터 `REQ_DEADLINE_PASSED`) · R-4 ANNUAL·REMOTE·OFF 는 영업일만, HOLIDAY_WORK 는 주말·공휴일만 · R-5 같은 날 ANNUAL/REMOTE/OFF 중 하나만, 예외 REMOTE+OFF 허용 · R-6 제출(PENDING) 시점에 잔여 예약 차감, 반려·취소 시 반환 · R-7 본인이 기한(직전 영업일 17:00)까지 취소 가능, 이력 기록 · R-8 `REQUIRE_APPROVAL` · R-9 사용일이 되었는데 PENDING 이면 효력 없음(소급 승인 없음).

**잔여** — L-1 입사 다음 달 같은 날부터 매월 +1 · L-2 그 날짜가 없는 달은 말일 · L-3 잔여 = 적립 누계 − 사용·예약(APPROVED+PENDING), 소멸·상한 없음 · L-4 미래 날짜 연차도 **신청 시점 잔여**로 검사(가불 불가) · L-5 재택은 사용일이 속한 달 기준 2회, 다음 달 신청은 다음 달 한도에서 차감 · L-6 OFF 만료 = 근무일 + 30일의 23:59:59 · L-7 사용일이 만료 이전이어야 하며 만료가 빠른 OFF 부터 차감(FIFO) · L-8 만료는 배치 없이 조회 시 계산 · L-9 잔여는 저장값이 아니라 `balance_ledger` 원장에서 매번 계산.

**대시보드 상태 우선순위** — 연차 → 퇴근(지각·조퇴·직접 입력 배지) → 근무중(연구실/재택/주말 근무) → 재택 예정 → 미출근(10:00:01 이후 "지각 위험") → 휴무. 반일 OFF 사용일은 `OFF` 배지 추가.

## 3. 구현하면서 내린 결정

> 문서로 판단할 수 없는 부분은 "사용자에게 불리하지 않으면서 악용 여지가 적은" 쪽을 골랐습니다.

| D-23 | 공휴일 추가·삭제로 그날의 영업일 여부가 바뀔 때, 그날 **진행 중(PENDING)·승인(APPROVED) 신청이 있으면 막는다** (`409 HOLIDAY_HAS_REQUESTS`). 평일을 공휴일로 추가 → 연차·재택·OFF 신청이 있으면 거부, 평일 공휴일을 삭제 → 주말/공휴일 근무 신청이 있으면 거부. 리드가 해당 신청을 먼저 반려(팀원은 취소)한 뒤 공휴일을 바꾼다. 주말은 공휴일 여부와 무관하게 영업일이 아니라 검사하지 않는다. | 원문에 정해져 있지 않다. 자동으로 연차를 돌려주거나 신청을 무효화하면 차감 이력과 결재가 사용자 모르게 바뀐다. 막고 사람이 정리하게 하는 편이 추적 가능하다. |
